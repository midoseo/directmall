# 카페24 상세페이지 변환 규격 (v3.1)

이 레포의 상품 상세페이지 HTML을 카페24 상품 상세설명에 넣기 위한 변환 규격.
`convert_detail.py` 가 이 규격을 코드로 구현한 것이며, 문서는 그 근거를 설명한다.

---

## 1. 전제 — 왜 일반적인 반응형이 안 되는가

카페24 스킨에서 `product/detail.html` 에는 **`<head>` 영역이 없다.** `<head>` 는 공통 레이아웃
(`layout/basic/layout.html`)에 있고, 현재 PC 스킨은 **고정폭 비반응형**이라
`<meta name="viewport" content="width=device-width">` 를 추가하면 몰 전체가 깨진다.

즉 **상세설명 HTML은 viewport 메타가 없는 환경에서 동작해야 한다.**

기존 페이지는 `@media (max-width:560px)` 로 분기했는데, 상세설명은 스킨 **그리드 컬럼 안**에
삽입되므로 화면 폭과 컬럼 폭이 달라 분기가 동작하지 않았다. → 글자·이미지 깨짐의 직접 원인.

**해결: 반응 기준을 화면 폭이 아니라 컨테이너(컬럼) 폭으로 바꾼다.**

```css
.lucell{ container-type: inline-size; container-name: lud; }
@container lud (max-width:620px){ ... }
```

## 2. 소스 템플릿 구조

기존 상세페이지는 전부 동일 템플릿이다. 이 구조를 벗어나면 변환 전에 확인이 필요하다.

```html
<body>
  <div class="safe">          <!-- 최상위 래퍼 (→ .lucell 로 변경) -->
    <section class="hero">...</section>
    <section class="sec intro">...</section>
    <section class="sec why"><div class="grid"><div class="feat">…×6</div></div></section>
    <section class="sec art">...</section>
    <section class="life">...</section>       <!-- full-bleed + .overlay -->
    <section class="sec fp">...</section>
    <section class="fire">...</section>
    <section class="sec spec"><table>...</table></section>
    <section class="sec faq"><div class="qa"><div class="q"><div class="a"></section>
    <section class="sec guide"><div class="g-wrap"><div class="g-block"><table class="g-table">
    <footer class="foot">...</footer>
  </div>
</body>
```

AED 계열은 여기에 `.art-diagram / .callout / .cdot / .lrow / .clabel`(부품 콜아웃),
`.parts .thumbs`, `.holder .thumbs`, `.rec-cards`, `.law .art-box` 가 추가된다.

**적용 완료 상품(12종)**: SFS10045, 10046, 10047, 10048, 10049, 10050, 10051, 10052, 10053,
AED10002, AED10011, AED10021

## 3. 변환 규칙 (convert_detail.py 구현 내용)

| # | 규칙 | 이유 |
|---|---|---|
| 1 | `.safe` → `.lucell` (CSS·마크업 전부) | `safe` 는 범용어라 스킨 CSS와 충돌 위험 |
| 2 | `<html>/<head>` 제거, `<style>` + `<div class="lucell">` 만 출력 | 상세설명은 body 조각만 들어감 |
| 3 | Pretendard `<link>` → `<style>` 안 `@import` | `<head>` 가 없어 `<link>` 를 못 씀. 폰트 미로딩 시 제목 자간이 뭉개짐 |
| 4 | `.lucell` 에 `container-type:inline-size; container-name:lud` | 핵심. 컬럼 폭 기준 반응 |
| 5 | 모든 `font-size:Npx` → `font-size:Npx; font-size:clamp(min, K cqi, Npx)` | 앞의 px = 구형 브라우저 폴백. `K = N/780*100` → 컨테이너 780px 이상에서 원본 크기 |
| 6 | 원본 `@media (…)` → `@container lud (…)` 로 전환 | 화면 폭 → 컬럼 폭 |
| 7 | 6번의 원본 `@media` 는 `@supports not (container-type:inline-size)` 안에 그대로 보존 | 컨테이너 쿼리 미지원 브라우저 폴백 |
| 8 | `.grid` → `repeat(auto-fit, minmax(150px,1fr))` | 미디어쿼리 없이 3열→2열→1열 자동 |
| 9 | `.thumbs figure` 고정 % 폭 → `flex:1 1 Npx` | 좁은 컬럼에서 min-width 때문에 넘치는 것 방지 |
| 10 | base64 인라인 이미지 → `images/imgNN.ext` 파일로 분리 | AED 3종이 415~433 KB였음. 분리 후 25~28 KB (94% 감소) |
| 11 | `<img>` 에 쓰인 클래스의 크기·위치 선언을 `!important` 로 재선언 | 방어 규칙의 `max-width:100% !important` 가 `.hero-img{max-width:420px}` 등을 덮는 것 방지 |

### 스킨 CSS 방어 규칙

```css
.lucell *{box-sizing:border-box !important;}
.lucell img{display:block !important;max-width:100% !important;height:auto !important;}
.lucell table{width:100% !important;max-width:100% !important;}
```

`height:auto !important` 는 카페24 "상세 이미지 자동 리사이즈" 가 `<img>` 에 강제 `width` 를
주입해 세로 비율이 깨지는 것을 막는다. (관리자에서 해당 옵션 해제 권장)

## 4. ⚠️ 실패 사례 — 반드시 지킬 것

### 표 셀에 `overflow-wrap:anywhere` 를 쓰지 말 것

v3.0에서 표 넘침을 막으려고 아래처럼 넣었다가 **표가 붕괴**했다.

```css
/* ✗ 절대 금지 */
.lucell th,.lucell td{overflow-wrap:anywhere;}
.lucell th{white-space:normal !important;}
```

`anywhere` 는 `break-word` 와 달리 **min-content 폭 계산까지 바꾼다.** "4층 이상" 의 최소 폭이
1글자로 계산되면서, 표 자동 레이아웃이 해당 열을 1글자 폭으로 짜부라뜨려 글자가 세로로 떨어졌다.
게다가 원본의 `th{white-space:nowrap}` 을 `!important` 로 덮어 붕괴가 확정됐다.

```css
/* ✓ 올바른 처리 */
.lucell p,.lucell li,.lucell h1,.lucell h2,.lucell h3,.lucell h4{
  word-break:keep-all;overflow-wrap:anywhere;}   /* 본문에만 anywhere */
.lucell th,.lucell td{word-break:keep-all;overflow-wrap:break-word;}
.lucell th{white-space:nowrap;}                  /* 원본 동작 유지 */

@container lud (max-width:620px){                /* 좁을 때만 해제 */
  .lucell table{table-layout:fixed;}
  .lucell th{white-space:normal;}
}
```

### CSS 블록 순서 유지

```
1. @import (Pretendard)
2. 원본 디자인 CSS       ← 색상·톤 그대로. 폰트크기만 유동화
3. 컨테이너 선언 + 방어 규칙
4. 그리드/썸네일 유동화
5. 이미지 개별 캡 재선언
6. 컨테이너 폭별 여백 전환
7. 원본 @media → @container
8. @supports 폴백
```

### 공통 CSS 파일로 분리하지 말 것 (현 시점)

모델별로 액센트 컬러가 다르다 (메타큐브 20L `#7b83c4` / 40L `#8f6fc6` / 루셀 `#b78e4e` /
이지스 `#4a5a70` / AED `#d0384a`). 공통화하려면 CSS 변수 리팩터링이 필요하고,
현재 12종 규모에서는 실익보다 리스크가 크다. **각 상품 HTML 자기완결 구조를 유지한다.**
상품이 30~40종으로 늘면 그때 재검토.

## 5. 사용법

```bash
python3 convert_detail.py <입력.html> <출력디렉터리> --name "도어락 A" --code SFS10054

# 원본에 images/ 폴더가 있으면 함께 복사
cp -r src/doorlock_a/images out/DOORLOCK_A/
```

### 검증 항목

- [ ] `class="safe"` 잔존 0
- [ ] `data:image` 잔존 0
- [ ] CSS 중괄호 균형
- [ ] `<img src>` 참조 파일 모두 존재
- [ ] 브라우저로 열어 창 폭을 줄였다 늘렸을 때 부드럽게 대응
- [ ] **표의 열이 붕괴하지 않는가** (4항 참조)
- [ ] 이미지 세로 비율 정상

## 6. 남은 이슈 (상세설명으로 해결 불가)

모바일에서 페이지 전체가 축소 렌더링되는 문제는 **공통 레이아웃의 viewport 메타 부재**가 원인이며,
상세설명 HTML로는 해결할 수 없다. 에이전시에 아래 두 안의 견적을 요청한 상태.

1. 모바일 전용 스킨 분리 운영 (카페24 기본 기능) — 빠르고 저렴
2. PC 스킨 반응형 전환 + viewport 메타 적용 — 근본 해결
